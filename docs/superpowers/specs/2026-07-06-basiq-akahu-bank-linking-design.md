[Spec]

> **Supersedes the earlier `[Spec]`/`[Plan]` comments on GitHub issue #323.** Those were written before #320 shipped and describe an architecture that does not match what actually landed: a `BankProvider` async-trait, a `bank_providers/` submodule directory, and SvelteKit file-based routes. The real #320 foundation is a closed `Provider` **enum** (`bank_provider.rs`) with `match`-based dispatch (`bank_linking.rs`), one flat file per provider (`gocardless.rs`, `financial_connections.rs`), and a Svelte 5 Vite SPA (no SvelteKit, no `routes/` directory). This spec builds against the real foundation.

## Brief

> As a Nels Pro subscriber banking in Australia or New Zealand, I want to link my bank account via Basiq (Australia) or Akahu (New Zealand — a purpose-built NZ-only aggregator, chosen over Basiq's partial NZ coverage), so that my transactions import automatically, matching the experience #303 provides for US subscribers via Stripe Financial Connections.
>
> Acceptance Criteria:
> - A Pro subscriber with a bank account in Australia can start a Basiq consent flow (CDR-based) and link one or more accounts to a budget.
> - A Pro subscriber with a bank account in New Zealand can start an Akahu consent flow and link one or more accounts to a budget.
> - A non-Pro user is blocked from starting either link flow and shown an upgrade prompt, same as #303.
> - Linked accounts' transactions import into the existing `transactions` table, attributed to the active budget at import time, recording `currency = 'AUD'` or `'NZD'` as applicable — no FX conversion.
> - Transactions refresh automatically via each provider's webhook/event notifications, plus manual refresh.
> - A user can view linked accounts (from either provider) and disconnect one; disconnecting stops future imports without deleting history.
> - Linking and status are reachable from chat for both providers.
> - If a subscription lapses, refresh stops for Basiq- and Akahu-linked accounts without deleting them.

## Assumptions

1. **Base architecture is #320's real, shipped shape**, not the stale comment's trait/directory design: extend the `Provider` enum (`bank_provider.rs`) with `Basiq`/`Akahu` variants, add `basiq.rs`/`akahu.rs` as flat sibling modules to `gocardless.rs`/`financial_connections.rs`, and add `match` arms to `bank_linking.rs`'s `provider_of`-dispatch functions. No trait, no submodule directory, no SvelteKit routes.
2. **Basiq's real consent UX is hosted, not institution-list-driven.** Unlike GoCardless (where Nels fetches an institutions list and the user picks a bank in Nels's own UI before redirecting), Basiq's actual product is "Basiq Connect": Nels creates a Basiq user + a CLIENT_ACCESS token scoped to that user, then redirects to Basiq's own hosted consent page where the user searches for and authenticates with their bank. Nels never needs its own institution picker for Basiq. `start_link_session` therefore takes no `institution_id`/`country` argument (Basiq is AU-only in this app).
3. **Akahu's real consent UX is also hosted (OAuth2 "Akahu Connect").** Nels redirects to `https://oauth.akahu.nz/authorize?...` with its app's `client_id`; Akahu's own hosted UI handles NZ-bank selection and authentication. Nels never needs an institution picker for Akahu either. The redirect returns an authorization `code` that Nels exchanges server-side for an access token.
4. **`bank_link_sessions` (added by #320 for GoCardless's pending-consent state) is generalized, not duplicated.** Add a `provider` column (`CHECK IN ('gocardless','basiq','akahu')`, default `'gocardless'` for existing rows) and relax `institution_id`/`institution_name`/`country` to nullable (Basiq/Akahu don't know the institution until the hosted flow completes). The existing `requisition_id` TEXT column is reused generically as "provider-side session/job reference" for Basiq/Akahu too (a rename was considered and rejected — it only touches a few call sites in `gocardless.rs` today and renaming risks an unrelated regression there for no behavior change).
5. **Shared-connection-scoped disconnect, not per-provider-account.** Basiq's connections API groups multiple bank accounts under one consent ("connection"); disconnecting one `linked_accounts` row must only revoke the Basiq-side connection when it is the LAST active local row referencing that connection id (stored in `provider_ref`) — otherwise the sibling accounts under the same consent would silently lose Basiq-side access while their local rows still say `active`. Akahu goes further: one Akahu access token can cover a user's accounts across *multiple* NZ institutions, so revoking it on a single-row disconnect would break every other Akahu-linked account for that user. Akahu's `disconnect_linked_account` is therefore **local-status-only** — it flips this row to `disconnected` but never calls Akahu's token-revoke endpoint. This is a deliberate, documented product tradeoff (favoring not breaking a user's other accounts over fully severing provider-side access on every disconnect), not an oversight.
6. **Webhook signature scheme: HMAC via the existing `billing::verify_stripe_signature` helper, not each provider's real native scheme.** Basiq's real webhooks are HMAC-signed (compatible with this approach). Akahu's real production webhooks are RSA-signed against a published, rotating public key — implementing full RSA verification (fetching and caching `https://api.akahu.io/v1/keys`, verifying against the correct key by `keyId`) is out of scope for this ticket's 3-day estimate. Akahu's webhook handler in this ticket verifies via a **shared-secret HMAC** (`AKAHU_WEBHOOK_SECRET`) using the same `t=...,v1=...` scheme Stripe/Basiq use, reusing the existing, already-unit-tested `verify_stripe_signature` helper rather than adding a new crypto dependency. This is called out explicitly as a known gap in Risks below and must not be read as "real Akahu signature verification is implemented."
7. **No backup poll for Basiq/Akahu**, unlike GoCardless (#320), which polls because it has *no* webhook at all. The AC for this ticket explicitly calls for "webhook/event notifications... plus manual refresh" — a missed webhook means the user relies on manual refresh until the next event, which is accepted for v1 (see Risks).
8. **Currency is hardcoded per provider, not read from the payload**, mirroring Stripe FC's hardcoded `'USD'` (`financial_connections.rs` comment: "Stripe FC in this codebase is US-only, so hardcoding 'USD' here is a correct, not guessed, value"). Basiq is AU-only (`'AUD'`) and Akahu is NZ-only (`'NZD'`) in this app, so the same reasoning applies — no FX conversion, per the AC.
9. **Amount normalization**: Basiq transaction amounts are decimal strings (e.g. `"-52.30"|"1500.00"`), the same shape GoCardless already uses — reuse `gocardless::normalize_amount` (already `pub(crate)`) rather than duplicating it. Akahu transaction amounts are signed JSON floats in dollars (not cents) — a small dedicated `akahu::normalize_amount(f64) -> f64` (`.abs()`) is added for symmetry/testability, mirroring the "pure, independently unit-tested" convention `financial_connections.rs`/`gocardless.rs` both follow.
10. **Category guess reused as-is**: both new providers call the existing `financial_connections::guess_category_id` heuristic (case-insensitive substring match against budget category names) — no new categorization logic.
11. **Pro-gating and permission-gating mirror the existing per-module `require_pro` convention** (each provider module defines its own `pub(crate) async fn require_pro`, not a shared cross-cutting helper — matches `financial_connections.rs`/`gocardless.rs` exactly, per the architecture briefing). Disconnect and view are NOT Pro-gated (a lapsed-Pro user can still see/manage their own data); start-link and manual-refresh ARE Pro-gated.
12. **Frontend reuses the existing generic redirect-completion channel.** `ChatResponse.bank_link_redirect_url` (already provider-agnostic, introduced for GoCardless) is reused for both Basiq's and Akahu's chat-triggered link flow — no new chat-response field needed. Two new query-param handlers (`?basiq_ref=...`, `?akahu_ref=...&code=...`) are added to `App.svelte`, mirroring `handleGoCardlessQueryParams` exactly.
13. **Country routing**: `Provider::for_country("AU") == Some(Provider::Basiq)`, `Provider::for_country("NZ") == Some(Provider::Akahu)`. New Zealand never routes to Basiq, closing the ticket's own explicit design note.
14. **The enum-dispatch choice still holds with 4 variants.** `AGENTS.md` §15 notes the enum-over-trait tradeoff was made for a *two*-member set and flags that "a hypothetical third provider would warrant revisiting this." This ticket brings the set to four (Stripe, GoCardless, Basiq, Akahu). Four flat `match` arms across `bank_provider.rs`/`bank_linking.rs`/`rag.rs`'s `LINK_BANK_ACCOUNT` arm is still small and readable — no per-provider behavior is complex enough to need dynamic dispatch, and two more independent single-country provider tickets (#321 Plaid, #322 Belvo) are landing concurrently on the same base, each adding one more arm. Revisiting the enum-vs-trait tradeoff is explicitly deferred to whoever integrates all four/six variants together (the epic's follow-up), not silently reopened here.

## Goal & Success Criteria

Goal: give Pro subscribers in Australia and New Zealand the same "link once, transactions flow automatically" outcome #303/#320 give US/European subscribers, via Basiq and Akahu respectively, built on #320's real `Provider` enum/dispatch layer.

Success criteria:
- `Provider::for_country("AU")`/`("NZ")` resolve to `Basiq`/`Akahu`; `supported_countries()` lists 11 entries.
- A Pro user can start a Basiq consent session (redirect URL returned), complete it, and see one or more `linked_accounts` rows with `provider = 'basiq'` plus zero-or-more imported `transactions` rows with `currency = 'AUD'`.
- A Pro user can do the same for Akahu (`provider = 'akahu'`, `currency = 'NZD'`).
- A non-Pro user gets a 402 with the standard upgrade-prompt string on both providers' start-link and manual-refresh calls, and makes **zero** external HTTP calls to Basiq/Akahu in that case.
- `bank_linking::refresh_linked_account`/`disconnect_linked_account` dispatch correctly for `basiq`/`akahu` rows (new `match` arms).
- Basiq's and Akahu's webhook handlers verify a signature, gate on the owner still being Pro before syncing, and are mounted as public routes.
- `rag.rs`'s `LINK_BANK_ACCOUNT` chat action supports `AU`/`NZ`; `LIST_LINKED_ACCOUNTS`/`UNLINK_BANK_ACCOUNT`/`REFRESH_BANK_ACCOUNT` require no changes (already provider-agnostic via `bank_linking.rs`).
- Frontend country picker includes Australia/New Zealand; linking either kicks off the matching redirect flow; return-trip completion works via new query params.

## Scope

**In:** `basiq` and `akahu` modules; hosted-redirect consent flows for each; account/transaction fetch; webhook handling (HMAC-verified); disconnect (connection-scoped for Basiq, local-only for Akahu); `bank_link_sessions` generalization; chat wiring; frontend country picker + redirect-return handlers.

**Out:** GoCardless/Plaid/Belvo (separate tickets, #320/#321/#322); FX conversion; real Akahu RSA webhook-signature verification (documented gap); business/joint accounts beyond what #303/#320 already handle; per-account (vs. per-connection) Basiq disconnect granularity beyond the "last active row" rule in Assumption 5.

## Architecture

- **`backend/src/bank_provider.rs`**: add `Provider::Basiq`, `Provider::Akahu`; extend `as_str`/`parse`/`for_country`/`supported_countries()`. Existing tests extended, not restructured.
- **`backend/src/basiq.rs`** (new, mirrors `gocardless.rs`'s shape): `require_pro`, `create_consent_session` (Pro/edit/not-closed-gated; creates a Basiq user + CLIENT_ACCESS token, persists a `bank_link_sessions` row, returns the hosted consent redirect URL + session reference), `complete_consent_session` (re-fetches the Basiq user's accounts server-side, persists `linked_accounts` rows with `provider='basiq'`, initial best-effort sync), `sync_account_transactions` (closed-budget no-op, idempotent insert, `currency='AUD'` hardcoded), `refresh_linked_account` (Pro-gated, synchronous — same shape as GoCardless's manual refresh), `disconnect_linked_account` (connection-scoped per Assumption 5), `webhook` (public handler, HMAC-verified, Pro-gate-before-sync).
- **`backend/src/akahu.rs`** (new, same shape): `require_pro`, `create_consent_session` (builds the Akahu OAuth authorize URL, persists a `bank_link_sessions` row keyed by a `state` value), `complete_consent_session` (exchanges the returned `code` for an access token, fetches accounts, persists `linked_accounts` rows with `provider='akahu'`), `sync_account_transactions`, `refresh_linked_account`, `disconnect_linked_account` (local-status-only per Assumption 5), `webhook`.
- **`backend/src/bank_linking.rs`**: add `"basiq"`/`"akahu"` arms to `provider_of`-based `refresh_linked_account`/`disconnect_linked_account` dispatch; add `basiq_start_link_handler`/`basiq_complete_link_handler` and `akahu_start_link_handler`/`akahu_complete_link_handler` REST handlers (mirroring the `gc_*` ones).
- **`backend/src/main.rs`**: `mod basiq; mod akahu;`, new routes (`.../basiq/session`, `.../basiq/complete`, `.../akahu/session`, `.../akahu/complete`, plus public `/basiq/webhook`, `/akahu/webhook`), no new background ticker (Assumption 7).
- **`backend/src/rag.rs`**: extend the `LINK_BANK_ACCOUNT` match arm with `Provider::Basiq`/`Provider::Akahu` cases (calling the new `create_consent_session` functions, setting `bank_link_redirect_url`); extend the system-prompt country list (line ~1425) and `offline_country_hint` with Australia/New Zealand. `LIST_LINKED_ACCOUNTS`/`UNLINK_BANK_ACCOUNT`/`REFRESH_BANK_ACCOUNT` need no code changes (already provider-agnostic).
- **Migration**: one new timestamped file generalizing `linked_accounts.provider` CHECK and `bank_link_sessions` (Assumption 4).
- **Frontend**: `LinkedAccounts.svelte`'s country picker gains Australia/New Zealand options and branches to the matching start-link call; `linkedAccounts.js` gains `fetchBasiq*`/`fetchAkahu*` thin wrappers (mirroring the `fetchGc*`/`startGc*` ones); `App.svelte` gains `handleBasiqQueryParams`/`handleAkahuQueryParams` mirroring `handleGoCardlessQueryParams`.

## Error Handling & Edge Cases

- Abandoned consent (user closes the hosted Basiq/Akahu page before finishing) → no `linked_accounts` row created; the `bank_link_sessions` row stays `pending` forever (same as GoCardless's existing behavior — no cleanup job exists for stale pending sessions today, so this ticket does not add one either, consistent with the existing convention).
- Basiq/Akahu API or webhook error → same graceful-degradation shape as #303/#320 (`BAD_GATEWAY` + logged, no partial-success ambiguity).
- Re-linking an already-linked `provider_account_id` into a different budget → rejected with `409 CONFLICT`, same guard as #303/#320's `complete_link_session`.
- Non-Pro user hits any Pro-gated Basiq/Akahu path → `402` with the exact existing upgrade-prompt string, before any external HTTP call is made (verified via `wiremock .expect(0)`, same pattern as #320's tests).
- Closed (project) budget → all sync paths (initial link, manual refresh, webhook-driven) short-circuit to a clean no-op, mirroring `financial_connections.rs`/`gocardless.rs`'s `closed_at` check.
- Subscription lapse → webhook-driven sync checks owner's Pro status before syncing (same as Stripe FC's webhook and GoCardless's poll); accounts are never deleted, only skipped.

## Testing Approach

- Pure-function unit tests (no DB/network): `Provider::for_country`/`supported_countries` additions; Basiq/Akahu amount normalization; category-guess reuse needs no new test (already covered); webhook-event-mapping pure parsers (mirrors `map_fc_webhook_event`).
- `#[ignore]`d `wiremock`-backed integration tests mirroring `gocardless.rs`'s/`financial_connections.rs`'s exact style: non-Pro 402 + zero external calls, Pro user completes a link and gets a `linked_accounts` row, sync idempotency (re-sync imports 0 new rows), disconnect (connection-scoped for Basiq, local-only for Akahu — asserting the Basiq API delete is/isn't called depending on sibling-row presence, and asserting Akahu's disconnect makes **zero** external calls), webhook signature rejection, webhook-driven sync skips a lapsed-Pro owner.
- `bank_linking.rs` dispatch test extended with a `basiq`/`akahu` case (mirrors the existing `refresh_dispatches_to_gocardless_for_a_gocardless_row` test).
- Frontend: extend `linkedAccounts.test.js` with pure-function tests for the new `fetchBasiq*`/`fetchAkahu*`/`startAkahu*` helpers, mirroring the existing GoCardless helper tests.

## Risks & Open Questions

- **Akahu webhook signature verification is HMAC, not the real RSA scheme** (Assumption 6) — a documented gap, flagged again in the Plan's "Known Plan Gaps", not silently shipped as if it were production-grade Akahu verification.
- **No backup poll** (Assumption 7) means a lost webhook delivery is only recovered by the user's own manual refresh — acceptable for v1 per the AC's explicit wording, but worth flagging if webhook reliability turns out to be poor in practice.
- **Basiq's real hosted-consent completion signal** — this ticket assumes the redirect-back from Basiq's hosted page implies the consent job is far enough along that fetching the user's accounts immediately succeeds (mirrors GoCardless's identical assumption about its requisition being ready at redirect time). If Basiq's job is still processing at that moment, the initial `complete_consent_session` call may import 0 accounts; the webhook (once it fires) is the actual source of truth for "the connection is ready," so this is a soft UX gap, not a correctness bug — same tradeoff GoCardless already accepted.
- Two independent provider integrations in one ticket (3-day estimate, same size class as #320).
